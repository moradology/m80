# Direct URL Fixture Harness

Direct official bundle URL tests use a network-free release fixture. The
fixture writes a complete `moradology/m80` release material set into a temporary
directory, shadows `curl` through `PATH`, and serves files by release asset
name. The fake `curl` records every requested URL in `M80_FAKE_CURL_LOG`.
Tests assert request order and prove the verifier did not fetch the bundle before required pre-bundle material passed.

The complete fixture is generated by
`write_direct_release_materials_with`. It computes SHA-256 digests from the
generated bytes for the bundle, metadata, sidecars, `install.sh`, asset index,
bootstrap selector, build manifest, `SHA256SUMS`, release-integrity predicate,
and release-attestation metadata. Negative scenarios intentionally replace or
omit those computed values rather than relying on checked-in stale bytes.

The fixture matrix covers:

- complete official release material;
- missing material, modeled as a fake network failure for that asset name;
- mismatched repository or release tag in signed release material;
- tampered bundle bytes;
- stale asset-index rows;
- stale checksum sidecars;
- missing `install.sh` digest rows in `SHA256SUMS`;
- stale public `SHA256SUMS` rows;
- bad release-integrity predicate subjects;
- failed or malformed GitHub attestation output.

The regression guard
`fixture_omit_matrix_covers_every_direct_url_material_class` compares the
verifier's material class/name list with the fixture omit matrix. Adding a new required verifier material class must add a fixture case, or the test fails.
