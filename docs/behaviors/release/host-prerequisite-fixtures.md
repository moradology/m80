# Host Prerequisite Fixtures

The host prerequisite fixture matrix proves release/install checks without
mutating the operator's host. It builds a complete fake install root under a
temporary directory:

- `opt/firecracker/bin/firecracker`
- `opt/firecracker/bin/jailer`
- `opt/firecracker/bin/firecracker-seccomp-filter.bin`
- `opt/m80/bin/m80`
- `opt/m80/bin/m80-jailer-harden`
- `opt/m80/bin/m80-net-helper`
- `opt/m80/artifacts`
- `var/run/m80`
- `etc/m80/profiles/default.toml`

The fixture does not write `/opt`, `/etc`, real `/dev/kvm`, system cgroups, or
sudo state. Host substrate proof goes through
`verify_host_substrate_fixture()` and is labeled
`HostSubstrateProofKind::HostlessFixture`, so it cannot be mistaken for a
real-KVM launch proof. Host binary proof uses the same installed
`host-binaries.manifest.json` evidence shape generated by install and consumed
by preflight. The fixture does not claim the final unified verifier-result
contract; `m80-o3uh9.8.3.1` owns that result shape, and
`m80-o3uh9.8.3.2` owns the final root-owned file/mode/hash verifier core.

## Matrix Cases

`crates/m80-preflight/tests/host_prerequisite_fixtures.rs` covers:

- exact fixture success, including hostless substrate rows and a generated
  schema-current host-binaries manifest;
- wrong Firecracker train;
- stale installed-byte hash observable after manifest generation;
- missing jailer;
- missing Firecracker seccomp filter;
- helper that cannot run the version probe;
- install-root override, proving all final paths stay under the temp root.

The root-owned file/mode verifier is intentionally not simulated by changing
the real host. The final host-binary verifier core owns those root/mode checks;
the fixture matrix provides the temp-root path and manifest cases that future
result-contract, diagnostics, and install tests should reuse.

## Adding A Case

Add a new matrix row by mutating the fixture after `InstallRootFixture::new()`
and before `write_manifest()` or `prove_host_prerequisites()`. Keep the mutation
inside the fixture's temp root. If the new failure depends on host substrate,
change the `HostSubstrateFixture` input rather than probing the live host.
If the failure depends on final file identity, generate the manifest first,
mutate one fixture file, and assert the recorded manifest fact no longer matches
the current fixture bytes.
